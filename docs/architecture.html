Galley Architecture

01Decisions

The five calls everything else follows from.

Two of these are load-bearing. Git worktrees mean you never invent a proposal format, and asynchronous jobs mean a queue wait can never block a Claude turn. The rest is plumbing around them.

Isolation
One git worktree per Claude session Claude edits and commits on claude/<slug> in its own checkout. Your main working tree is never touched by an agent, so parallel sessions and rollback are free.
Diffing
Git is the diff substrate; the UI is a view The merge pane renders git diff main...claude/<slug>. No shadow copies, no bespoke patch format, no second source of truth about what changed.
Code
Mirror the codebase locally, execute remotely Clone the code repo onto the Mac so Claude reads and edits it with real Grep/Glob/Edit tools at local speed. Running it is a separate, explicit act that happens on the cluster.
Jobs
Experiments are objects, not turns A submitted job outlives the session that created it. Completion wakes a new Claude session with the results attached, rather than holding one open across a six-hour queue wait.
Authority
Prose merges are manual; numbers are generated You accept every sentence by hand. You never accept a number by hand — figures reach the PDF only through \input{} of a file built from a results artifact.

No agent process runs on the cluster. The cluster is a job executor reached over SSH; all reasoning about code happens against the local mirror.

Why mirror instead of running Claude on the login node

Agents on a login node are a bad trade: shared-machine credential storage, restrictive process policies, and no LaTeX toolchain. Mirroring costs you one git pull and buys Claude full-speed local tools over the whole codebase.

03Worktrees

Session isolation, and how the agent is actually launched.

Creating a session is three git commands and a subprocess. The worktree is disposable; the branch is the record.

# galley/services/worktree.py
git -C paper worktree add .worktrees/ablation-lr -b claude/ablation-lr main
git -C paper/.worktrees/ablation-lr config user.name  "Claude (galley)"
git -C paper/.worktrees/ablation-lr config user.email "galley@localhost"

Then the agent, scoped to that worktree with the code mirror mounted read-write:

# galley/services/agent.py
from claude_agent_sdk import query, ClaudeAgentOptions

env = os.environ.copy()
env.pop("ANTHROPIC_API_KEY", None)   # else it bills the API, not your plan
env.pop("ANTHROPIC_AUTH_TOKEN", None)

opts = ClaudeAgentOptions(
    cwd=worktree_path,
    add_dirs=[CODE_MIRROR],
    permission_mode="acceptEdits",
    mcp_servers={"galley": {"type": "http",
                 "url": "http://127.0.0.1:7878/mcp"}},
    env=env,
)
async for msg in query(prompt=prompt, options=opts):
    await bus.publish(session_id, msg)   # -> SSE -> UI log
Subscription auth footgun

The SDK and CLI both use your logged-in Claude credentials only when no API key is present in the child environment. If ANTHROPIC_API_KEY is exported in your shell profile it silently inherits and bills per-token instead. Strip it explicitly at spawn and assert on it at startup.

Merging a session back is a normal git operation, which is the whole point — after you have accepted hunks in the merge pane, paper/ holds ordinary uncommitted changes you commit yourself. The worktree is then removed and the branch kept as provenance.

04Async jobs

The centerpiece. A scheduler queue is measured in hours; a Claude turn is measured in minutes.

This is the constraint the whole app is shaped around. If submit_job blocks until results exist, every session either times out or burns your rate limit idling. So submission returns immediately, and completion is an event that starts new work.

DRAFTClaude writes the run script + config into the code mirror, commits
SUBMITTEDrsync at pinned SHA, sbatch, capture scheduler id
PENDINGpoller runs squeue -j; the session that submitted has already ended
RUNNINGtail stdout on demand; UI streams the last N lines
COMPLETEDsacct exit 0 → pull artifacts/ back over rsync
HANDOFFnew Claude session opens with metrics.json in the prompt

A failed job takes the same path with the tail of stderr substituted for metrics, into a session prompted to diagnose rather than to write.

The poller

One asyncio task, not a thread per job. Poll interval backs off by state — thirty seconds while PENDING, five minutes while RUNNING — and every transition is written to SQLite before it is published to the UI, so a backend restart resumes cleanly.

# squeue is authoritative while queued; sacct after the job leaves the queue
ssh cluster "squeue -j $JID -h -o %T"          # PENDING|RUNNING|(empty)
ssh cluster "sacct -j $JID -n -X -o State,ExitCode,Elapsed"
Reproducibility comes free here

Because submission rsyncs a pinned commit rather than your dirty working copy, every artifact carries the exact SHA that produced it. Record it on the job row and print it into the results file — that is what makes the generated table in §07 trustworthy months later.

SSH without pain

Shell out to the system ssh rather than reaching for Paramiko: you inherit your existing ~/.ssh/config, jump hosts, and hardware-key agents for free. Add a ControlMaster block for the cluster host so a hundred status polls reuse one authenticated connection instead of paying a handshake each.

05Tool surface

What the backend exposes to Claude over MCP, and what it deliberately does not.

The API and the agent tools are the same FastAPI app. Claude gets a narrow, verb-shaped surface — enough to run science, not enough to publish.

Not exposed, on purpose

No git push, no git commit on main, no Overleaf credentials, no scancel for jobs the session did not create. Publishing and cancelling are yours. Bind the MCP server to 127.0.0.1 only.

06Merge UX

Line diffs are useless on LaTeX. This section is why the app exists.

A paragraph of LaTeX is frequently one very long line. A stock line-based diff reports it as wholly deleted and wholly re-added, which tells you nothing. Galley diffs at sentence granularity with word-level emphasis inside each changed sentence:

We evaluate on three benchmarks (§4.1).
− The model improves over the baseline by a large margin across all settings.
+ The model improves over the baseline by 4.2 BLEU on average, though the gain narrows to 0.8 on low-resource pairs.
We ablate the retrieval component in Table~\ref{tab:ablation}.

Sentence-level segmentation with intra-sentence word highlighting. Accept and reject act on the sentence, not the line.

Segmentation is a real module, with tests

Splitting LaTeX into sentences is where this gets fiddly. The tokenizer must not break on e.g., i.e., et al., Fig., Eq., cf., vs., decimals, or a period inside \cite{}; must treat inline math $...$ as opaque; and must pass % comments, \begin/\end blocks, and display math through as atomic units. Write it standalone against fixture files from your actual paper before wiring any UI to it.

Applying the merge

Do not hand-roll patch application. The merge pane holds the full resulting buffer, so accepting hunks is a client-side edit and the backend simply writes the final text to the file in paper/. Git is used to compute and display the diff, never to apply a partial one — that sidesteps the entire class of patch-offset and context-mismatch bugs.

@codemirror/merge's unifiedMergeView gives per-chunk accept/reject controls out of the box; feed it the sentence-segmented text and supply your own word-diff for the inline marks.

The second review surface

Text merging catches wording. It does not catch meaning. You already have latexdiff installed — run it between the accepted state and the proposed state, compile, and show the marked-up PDF beside the merge pane. Reading the change as it will appear in print is how you catch a claim that got quietly strengthened.

latexdiff paper/main.tex .worktrees/ablation-lr/main.tex > /tmp/diff.tex
latexmk -pdf -interaction=nonstopmode -outdir=/tmp /tmp/diff.tex

07Numbers

A hallucinated figure must not be able to reach the PDF.

This is worth designing in from the first commit, because retrofitting it means auditing every number already in the manuscript. The rule: no numeral is ever typed into a .tex file by hand or by agent. The path is one-way.

cluster run  →  artifacts/metrics.json      (pulled, immutable, carries git SHA)
             →  results/ablation-lr.json    (committed to the paper repo)
             →  tables/ablation.tex         (generated; never hand-edited)
             →  \input{tables/ablation}     (the only reference in main.tex)

What you review in the merge pane is therefore the JSON and the generated table together. If Claude invents a number, it appears as a results/*.json change with no corresponding job id — which the UI can flag mechanically, with no judgement required from you.

Cheap enforcement

A pre-commit hook on the paper repo that rejects a diff touching tables/ unless results/ changed in the same commit. Twenty lines, and it makes the invariant structural rather than aspirational.

08Overleaf

Treat it as a dumb single-branch remote with a second writer attached.

The Overleaf git bridge is not a normal remote. It exposes one branch, master; force-push is unreliable; and the web editor means the remote may have moved since you last looked — you are collaborating with yourself.

So the git panel gets exactly one compound button, Sync, which does:

  1. Refuse unless you are on main with a clean tree.
  2. git pull --rebase overleaf master.
  3. On conflict, route the conflicted files into the same merge pane from §06 — the sentence-level tooling is exactly right for reconciling two prose edits, and it means you never learn a second conflict UI.
  4. git push overleaf main:master.

Branches stay purely local. Claude's branches never go near the remote, so Overleaf only ever sees prose you already accepted.

Use plain subprocess around real git rather than GitPython or pygit2. Git's porcelain is stable, its plumbing (--porcelain=v2, --numstat) is designed for exactly this, and you avoid a library that will disagree with your terminal.

11Risks

Known sharp edges, with the mitigation decided in advance.

Billing Inherited API key

An exported ANTHROPIC_API_KEY silently diverts usage from your subscription to metered API billing. Strip it at spawn and fail startup loudly if it is set in the parent environment.

Correctness Tokenizer edge cases

A bad split shows a false diff and you accept a change you did not read. Mitigation: it ships in M2 with fixtures, and the latexdiff PDF is a second, independent view of the same change.

Integration Overleaf drift

Editing in the web editor between syncs guarantees eventual conflicts. Always rebase before push; never force. Accept that Overleaf is a peer, not a backup.

Ops Long-lived SSH

VPN drops, expiring Kerberos tickets, and MFA-gated hosts all break polling. Treat SSH failure as a job state (UNREACHABLE), not an exception, and surface it in the job board rather than crashing the poller.

Scope Building an IDE

The temptation is to add a LaTeX editor, autocomplete, bibliography management. Don't — you have an editor. Galley's only jobs are running the agent, merging its output, and moving bits to the cluster and Overleaf.

Rate limits Parallel sessions

Worktrees make it easy to run four agents at once and exhaust your subscription window. Cap concurrent sessions in config and show the usage from each result message in the UI.
